# Gaps

A memory that cannot say what it lacks will eventually lie by omission. Gaps make absence a first-class, named thing.

## Query-scoped gaps

Every `context` bundle and `think` answer ends with a gap report scoped to the question:

- **Missing entities** — you asked about a slug that has no live page.
- **Stale entities** — the entity and everything connected to it predate a staleness window.
- **Unreadable attachments** — relevant records carry attachments that are still being read, failed reading, unsupported, or held; the report names each file and state.
- **Answer limits** — sentences in the answer that name what would be needed ("I would need the meeting transcript to confirm").

## Standing gaps

The workspace also keeps addressable gap rows a person can review and settle in the dashboard: missing threads (a reply quotes a message never captured), contradictions between claims, unresolved identities, channels gone silent, and uncited claims that the think checker recorded.

## How builders should treat gaps

Render them. A gap report in your UI is the difference between "the agent didn't mention it" and "the memory does not hold it — here is what would fill it." Gaps are the product being honest, not an error state.
